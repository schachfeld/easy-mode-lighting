# Glow for iOS and Android (React Native)

The current Glow phone app, built with [Expo](https://docs.expo.dev/) (SDK 58) and React Native. Together with the Home Assistant add-on, it is the current version of Glow. It replaces the deprecated Tauri app in `src-tauri/`. It connects straight to Home Assistant and needs no Glow add-on or server.

The lighting logic is not duplicated. The app imports `packages/core` (Home Assistant client, room and group mapping, scenes, validation, colors, sign-in) and `src/live.ts` (optimistic light updates and command pacing) from the repository. Only the interface and the platform layer are written for React Native.

## What it does

Everything the deprecated Tauri phone app did:

- Sign in with your Home Assistant account in the system browser, or with a long-lived access token.
- Stay signed in. The sign-in is kept in the Keychain or the Android Keystore, and Glow reopens your home on launch. A sign-in Home Assistant no longer accepts is forgotten.
- Rooms from Home Assistant Areas, with **Other lights** for lights without an Area. Filter to rooms with lights on.
- Turn rooms and lights on and off and dim them. Lights follow sliders while you drag.
- Adjust a light or light group: brightness, a color wheel, color swatches, a white temperature slider and white presets.
- Show light groups as one card with the individual lights inside, or as separate lights (**Customize lights**).
- Create, edit and delete scenes with six color palettes or the room's current lights. The lights show the scene while you design it, and go back if you cancel. Scenes are saved to Home Assistant.
- Activate Glow and Home Assistant scenes, favorite them, and see which one is active.
- Turn every light off and undo it.
- Live updates from other devices, and reconnection when the app returns to the foreground or the network comes back.
- Firefly and Daylight themes.

It also has a demo home (**Explore a demo home** on the sign-in screen), the same sample home the web app shows without Home Assistant.

## Differences from the Tauri app

- **No passphrase vault.** The Tauri app falls back to a passphrase-protected Stronghold vault when a platform has no secure storage. iOS and Android always have secure storage, so the vault is not needed. A sign-in saved by the Tauri app cannot be read by this app; sign in once after switching.
- **Navigation** uses a tab bar (Rooms, Scenes, Settings) and a native stack. On iOS it is the system tab bar, which is Liquid Glass on iOS 26 and later; the system appearance follows the Glow theme so the glass matches it. Android keeps a tab bar in the theme's colors. Dialogs are bottom sheets, and the Android back gesture closes them.
- **Network requests** for sign-in and scenes use Expo's native fetch with redirects turned off, so tokens are only sent to the address you entered, as in the Rust code.

## Develop

Requires Node.js 22+, and Android Studio with an emulator, or Xcode on macOS.

```sh
cd native
npm ci
npm run android   # builds a development app and starts Metro
npm run ios       # macOS only
```

`android/` and `ios/` are generated by `npx expo prebuild` and are not committed. Configure native behavior in `app.json`.

Checks:

```sh
npm run typecheck
npx expo-doctor
```

`EXPO_PUBLIC_HA_CLIENT_ID` overrides the sign-in identity page, like `VITE_HA_CLIENT_ID` in the Tauri app. The default is the published page in `auth-client/`.

## Build a release APK

```sh
npm run build:android
# android/app/build/outputs/apk/release/app-release.apk
```

Without a release keystore, the APK is signed with the debug key. Configure signing, or use EAS Build, before distributing it.

## Release to TestFlight

There is no CI workflow for this app yet; build and upload from a Mac with Xcode. You need an App Store Connect API key with access to the Glow app (bundle ID `io.github.schachfeld.glow`), its key ID and issuer ID, and the team ID.

1. Look up the latest build number of the current version in App Store Connect. The new build needs a higher one.
2. Generate the iOS project from `app.json`. CocoaPods needs a UTF-8 locale:

   ```sh
   export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8
   npx expo prebuild --platform ios --clean
   ```

3. Set the build number. `app.json` does not set one, so it is `1` after prebuild:

   ```sh
   /usr/libexec/PlistBuddy -c "Set :CFBundleVersion <build>" ios/Glow/Info.plist
   ```

4. Archive, export and upload, signing with the API key:

   ```sh
   auth=(-allowProvisioningUpdates -authenticationKeyPath <AuthKey.p8> -authenticationKeyID <key ID> -authenticationKeyIssuerID <issuer ID>)
   xcodebuild -workspace ios/Glow.xcworkspace -scheme Glow -configuration Release \
     -destination 'generic/platform=iOS' -archivePath build/Glow.xcarchive \
     DEVELOPMENT_TEAM=<team ID> CODE_SIGN_STYLE=Automatic "${auth[@]}" archive
   xcodebuild -exportArchive -archivePath build/Glow.xcarchive -exportPath build/export \
     -exportOptionsPlist ExportOptions.plist "${auth[@]}"
   xcrun altool --upload-app -f build/export/Glow.ipa -t ios --apiKey <key ID> --apiIssuer <issuer ID>
   ```

   `ExportOptions.plist` sets `method` to `app-store-connect` and `teamID` to your team ID.

Expo copies `assets/icon.png` into the app's icon set. To confirm the icon is in a build, run `xcrun assetutil --info build/Glow.xcarchive/Products/Applications/Glow.app/Assets.car` and look for `AppIcon`.

The deprecated Tauri app uses the same bundle ID. Do not upload a Tauri build after a React Native one; testers would get the Tauri app as the newest build.
